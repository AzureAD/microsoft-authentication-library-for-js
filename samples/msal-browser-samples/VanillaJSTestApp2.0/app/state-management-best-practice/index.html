State Management Best Practice
What this sample demonstrates:

This sample shows the recommended pattern for using the OAuth state parameter when you need to preserve the user's location during authentication flows.

❌ ANTI-PATTERN (Do NOT do this):
msalInstance.loginRedirect({
    scopes: ["user.read"],
    state: window.location.pathname  // Security risk!
});
✅ RECOMMENDED PATTERN (Use this instead):
// Save URL to storage, get reference key
const stateKey = AuthStateStorage.saveReturnUrl(window.location.pathname);

msalInstance.loginRedirect({
    scopes: ["user.read"],
    state: stateKey  // Secure reference key
});
Why is this better?
  • Security: URLs with sensitive info aren't exposed in OAuth flow
  • Privacy: User paths remain private, not logged by auth servers
  • Flexibility: Can store complex state, not just URLs
  • Validation: URLs are validated to prevent open redirect attacks
