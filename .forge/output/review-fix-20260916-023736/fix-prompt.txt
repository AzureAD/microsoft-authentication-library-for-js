### 🟡 `dpop-nonce-cross-tab-clear-race`
**File:** lib/msal-browser/src/cache/BrowserCacheManager.ts
**Step:** review-logic | **Action:** fix | **Confidence:** high

The new WeakMap coordination works only for cache managers in the same realm. Separate tabs have separate maps but shared localStorage, allowing a pending pre-logout write to repopulate the nonce after another tab clears it and allowing stale cross-tab writes to win. Use a shared per-client generation/order marker or equivalent cross-tab coordination.

### 🟡 `dpop-nonce-cross-tab-race`
**File:** lib/msal-browser/src/cache/BrowserCacheManager.ts
**Step:** review-fresh-eyes | **Action:** fix | **Confidence:** high

The module-local WeakMap serializes only managers in one JavaScript realm. Because localStorage is shared across tabs, concurrent deposits or a logout racing a pending write in another tab can leave an older or post-logout nonce in the shared cache.

### 🟡 `dpop-nonce-ttl-not-enforced-at-rest`
**File:** lib/msal-browser/src/cache/BrowserCacheManager.ts
**Step:** privacy-review | **Action:** fix | **Confidence:** high

[RETENTION] [PII] The 24-hour DPoP nonce TTL is enforced only when the same issuer is read or when a later nonce write enumerates cache entries; there is no purge when a PCA initializes or during ordinary non-nonce use. DPoP nonces are opaque server-provided values and may act as pseudonymous session/browser identifiers, so an expired entry in localStorage can remain physically stored indefinitely if the app receives no further nonce challenge and the user does not explicitly clear/logout, despite the documented 24-hour expiry. Purge all expired nonce entries for the current client during cache/PCA initialization (and retain the existing read/write cleanup), with a test that seeds an expired localStorage entry from a prior session and verifies a newly initialized PCA removes it without a nonce read or write.

### 🟡 `dpop-storage-change-missing-compatibility-map-entry`
**File:** lib/msal-browser/src/cache/BrowserCacheManager.ts
**Step:** review-standards | **Action:** fix | **Confidence:** high

This change adds DPoP nonce persistence through the browser storage implementations but does not update `lib/msal-browser/docs/browser-compat-map.md`. The applicable documented instruction requires map updates when browser Web API usage changes; its Storage table currently describes only interaction state/token cache and does not identify nonce persistence, its fallback, or the same private-browsing/storage-partitioning limitations. Add the nonce use and fallback behavior to the relevant storage rows so consumers can assess the persistence guarantees of this new API.

### 🟡 `token-cache-missing-from-pca-interface`
